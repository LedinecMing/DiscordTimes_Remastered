# Внутриигровой редактор карт — ТЗ для агента

## 1. Назначение

Внутриигровой редактор карт для тактической стратегии в духе «Времен Раздора». Инструмент, в котором автор карт создаёт и настраивает сценарии: рисует ландшафт, расставляет строения и армии, пишет события с условиями и результатами, локализует тексты, тестирует и публикует карту.

Цель — сделать редактор, в котором картодел не тратит время на борьбу с инструментом, а занимается творчеством. Без вылетов, без ручного поиска багов, с возможностью откатить любое изменение и сравнить версии.

## 2. Принципы UX (обязательные)

Эти принципы заданы автором и не подлежат изменению. Любое окно и любая функция редактора должны им соответствовать.

1. **Докинг окон.** Любое окно можно оторвать, перетащить, закрепить в любой стороне главного окна или показать как вкладку. Аналогично VS Code / Blender.
2. **Меню действий сверху.** Файловое меню: открыть проект, сохранить, сохранить как, недавние, настройки, открытие окон. Аналогично File/Edit/View в классических редакторах.
3. **Переход к определению (Go-to-Definition).** Если в здании есть ссылка на персонажа для найма — Ctrl+Click на этом поле открывает редактор персонажа. Если событие ссылается на подчинённое событие — открывается редактор этого события. Применимо к любым cross-references между объектами.
4. **Search и Replace.** Поиск любого объекта по проекту с показом всех мест использования. Replace — заменяет все вхождения. Например, поиск «ополченец» показывает, где он нанят, в каких гарнизонах, в каких событиях.
5. **Find references.** По любому объекту — список всех мест, где он упомянут. Двойной клик — переход к месту использования.
6. **Отображение строк: оригинал + локаль.** Каждое текстовое поле показывает одновременно raw-строку (ключ локали или литерал) и локализованный текст для выбранного языка. На поля без локали — иконка warning.
7. **Выделение и копирование любых частей.** Можно выделить фрагмент карты, граф событий, группу персонажей, армию — скопировать и вставить в другой проект. Вставка создаёт новые ID с разрешением конфликтов.
8. **Только изменённые поля.** При редактировании события/строения показываются только поля, отличающиеся от дефолта. Скрытые поля добавляются вручную через dropdown с поиском. Кнопка «показать все» отключает фильтр.

Дополнительные принципы:
- Command Palette (Ctrl+Shift+P) — быстрый доступ к любой команде редактора по имени.
- Горячие клавиши для всех действий, конфигурируемые.
- Тёмная тема по умолчанию, переключаемая на светлую.
- Мини-карта в углу с переходом по координатам.
- Контекстное меню по правому клику на любом объекте: «редактировать», «перейти к», «найти упоминания», «дублировать», «удалить», «создать шаблон из этого».
- Статус-бар снизу: координаты курсора, активный инструмент, число ошибок/предупреждений валидаторов, текущая ветка git.
- Tooltips с документацией и подсказками на каждом поле.
- Inline validation — красная подсветка некорректного значения сразу при вводе.

## 3. Окна редактора

Приоритеты по плану автора (P1 — высший, P- — добавлены как необходимые).

### P1 — Map View
Главное окно, открывается по умолчанию. Содержит:
- Канвас с рендером карты, зум, пан, поворот.
- Панель инструментов: выбор инструмента (Кисть, Заливка, Линия, Прямоугольник, Лассо, Пипетка, Инфо), выбор материала (тайл, объект, декор, событие, армия, фонарь), размер кисти.
- Слои (переключаемые): Terrain / Decorations / Buildings / Armies / Event Points / Lights / Fog of War.
- Мини-карта с переходом по координатам.
- Подсветка наведённого и выбранного объекта.
- Multi-select (Shift+клик или рамка) для массовых операций.
- Контекстное меню по правому клику.

### P2 — Event Graph
Графовое представление всех событий карты. Узлы — события, рёбра — связи между ними.
- Типы рёбер: подчинённое событие (sub_event), отложенное событие (delayed_event), «если событие выполнено» (if_event_executed), «если событие не выполнено» (if_event_not_executed), «если вариант ответа» (if_event_answ).
- Группировка нескольких событий под одним именем (например, «Подай — принеси»), разворачивается по двойному клику.
- Фильтр по цвету события (8 цветов) и по типу (Global / Local / Talks / Quest).
- Поиск по имени события и по комментариям.
- Drag узла для перераскладки, авто-укладка.
- Подсветка циклов и подозрительных цепочек.
- Экспорт графа в PNG/SVG.

### P2 — Event List
Списочное представление событий. Дополнение к Event Graph.
- Колонки: ID, имя, цвет категории, группа, тип (Global/Local/Talks/Quest), привязка (building_id или координаты), активационное время, число условий, число результатов, иконка warning при проблеме.
- Поиск с фильтрами (по цвету, типу, группе, имени).
- Панель редактирования справа с схлопываемыми секциями: Общее / Conditions / EventResult / Message.
- В Conditions и EventResult — только ненулевые поля (см. принцип 8).
- Добавление поля — через dropdown с поиском.

### P5 — Building Editor
Окно настройки одного строения. Открывается двойным кликом на строении в Map View.
- Секции: идентификация (имя, описание, владелец), тип (Town/Village/Castle/Fort/Tavern/Market/Church/Forge/Port/Altar/Mine/Ruins/Bridges), владелец, гарнизон, рынок, библиотека заклинаний, найм, события, доходы, союзы, клад (для руин), позиция.
- При смене типа строения — предупреждение, если на него ссылаются события/армии.
- Все выпадающие списки — с поиском.

### P5 — Locale Manager
Окно работы с локализацией. Четыре блока:
- Словарь локалей: таблица ключ × языки. Поиск, inline-редактирование.
- Анализ неиспользуемых ключей: проход по всем полям проекта, поиск ключей, которых нет ни в одном поле.
- Анализ нелокализованных строк: поиск текстовых полей, где raw строка не является ключом локали.
- Импорт/экспорт .RUS (совместимость со старым форматом) с валидацией символов и разделителей.
- В окне редактирования строки показывается одновременно raw-строка и локализованный вид для выбранного языка.

### P6 — Bonus Editor
Окно настройки бонусов, применяемых к юнитам и предметам.

### P7 — Version Control
Окно работы с git как backend версионирования.
- Авто-коммит при сохранении с осмысленным сообщением.
- История коммитов: автор, дата, сообщение, переход к версии (preview).
- Сравнение версий (diff): для каждого изменённого поля — старое и новое значение.
- Ветвление для экспериментов, merge с разрешением конфликтов.
- Откат к любой версии.
- Push/Pull к удалённому репозиторию для бэкапа и совместной работы.

### P10 — Unit Editor
Окно редактирования юнита. Базовые свойства, защита по типам магии, боевые параметры, тип магии, модель и анимации. Кнопка «Предпросмотр в бою» (опционально).

### P10 — Item Editor
Окно редактирования предмета. Поля: имя, описание, цена (может быть отрицательной), флаг продажи, бонусы, иконка. Импорт из внешнего каталога (например, dt-items.github.io).

### P- — Map Info
Метаданные проекта: название, автор, версия, описание, настройки игры, размер карты, число объектов, поддерживаемые языки, дисклеймеры.

### P- — Map Statistics
Производная информация о карте:
- Наполненность (плотность объектов на единицу площади).
- Предполагаемый путь игрока — визуализация на мини-карте последовательности фонарей, локальных событий, точек интереса.
- Граф роста сложности — график тактической стоимости сюжетных битв.
- Список всех warnings и errors из валидаторов.
- Граф зависимостей флагов.

### P- — Validators Panel
Список всех проблем, найденных валидаторами. Колонки: severity (error/warning/info), категория, сообщение, локация, ссылка на баг гайда (если применимо), действия (перейти, авто-исправить, игнорировать).

### P- — Event Simulator
Пошаговый симулятор событий:
- Задание начального состояния: время, золото, мана, инвентарь, флаги, состояние армий, выполненные события.
- Play / Pause / Step Forward / Step Backward / Step Until Next Event.
- Breakpoint на событии и на условии.
- Лог: время, проверенное событие, выполненные/невыполненные условия с значениями, применённый результат, вызванные подчинённые события, показанные сообщения.
- Watch expressions — наблюдение за значениями конкретных полей State.

## 4. Библиотеки

Минимальный набор, без альтернатив:

- **egui** — UI-фреймворк (immediate-mode). Основной слой UI.
- **egui_dock** или **egui_tiles** — докинг окон.
- **egui_node_graph** — графовое представление событий.
- **eframe** — каркас приложения (окно, цикл, ввод).
- **wgpu** — рендер карты (под капотом egui).
- **git2** (libgit2 bindings) — версионирование.
- **serde + serde_json** — сериализация метаданных, шаблонов, конфигурации.
- **advini** — существующий в проекте парсер ini-формата (для save-файлов и совместимости со старым редактором).
- **alkahest** — существующий в проекте бинарный сериализатор (для финальной сборки карты).

Опционально (если будет нужен):
- **rhai** — встроенный скриптовый движок для процедурной генерации контента.

## 5. Требования к функционалу

Обязательные требования к редактору (помимо принципов UX):

### Undo/Redo
- Каждое пользовательское действие — команда с redo/undo.
- Составные операции (paste, merge project) — макрокоманды.
- Ограниченный undo-stack (например, 1000 команд), с авто-snapshot перед деструктивными операциями.
- Snapshot хранится отдельно, позволяет восстановить состояние даже если undo-stack переполнен.

### Валидаторы карты
Запускаются по кнопке Lint, автоматически перед сохранением, в фоне (debounced) для inline-подсветки. Каждый валидатор — отдельная проверка на известную проблему. Минимальный набор:

- **PatrolBounds** — радиус патруля не выходит за границы карты (вылет игры при выходе за нижнюю границу).
- **TacticalCostOverflow** — тактическая стоимость армии близка к переполнению (становится отрицательной → вылеты).
- **FlagPrefixConflict** — имена флагов, где один является префиксом другого (игра проверяет не тот флаг).
- **EventFunctionComboConflict** — недопустимые комбинации в одном событии: фонарик + заклинание, ожидание + подчинённое событие, битва в строении.
- **RadiusRangeCheck** — радиус фонарика от 0 до 24 (вылеты при выходе за диапазон).
- **MarketPriceRangeValidation** — диапазон цен рынка содержит хотя бы один артефакт (иначе игра зависает при запуске). Исключение: диапазон (0, 0) означает «любая цена кроме отрицательной».
- **EventTextRequired** — функции события, не работающие без текста (получение артефактов, изучение заклинаний, добавление юнитов), предупреждать, если в событии пустое сообщение.
- **BuildingTypeChange** — предупреждение при смене типа строения, если на него ссылаются события/армии.
- **EmptyMapArmyActivation** — нельзя активировать армию на пустой карте без строений/декора.
- **SelfLoopWithoutText** — событие-сплетня без текста, вызывающее само себя через 0 часов (визуальные баги).
- **UnusedLocaleKeys** — поиск ключей локали, не используемых ни в одном поле.
- **QuestChainIntegrity** — для каждого задания есть событие-инициатор и событие-завершение.

Каждый валидатор имеет:
- Severity: error (блокирует сохранение), warning (сохранение возможно), info.
- Auto-fix, если применимо (например, обрезать радиус до 24).
- Ссылку на описание бага в гайде.

### Версионирование (git)
- При создании проекта — инициализация git-репозитория.
- Каждое сохранение — авто-коммит с сообщением «[map-editor] {action} {object_type} {object_name}».
- Группировка изменений: серия правок в одном окне — один коммит, переключение на другое окно — закрытие предыдущей группы.
- Игнорируемые файлы: snapshots, cache, временные бэкапы.
- Ветки: main (стабильная), experiment/* (эксперименты), release/* (версии для публикации).
- Теги: v1.0, v1.1, ... — версии для публикации.
- Pre-commit hook — запуск валидаторов, abort при errors.
- Push/Pull к удалённому репозиторию для бэкапа и совместной работы.

### Локализация
- Строковый ключ → переводы на N языков.
- Хранение: отдельный файл locales.json в проекте.
- В любом текстовом поле — одновременный показ raw и локализованного вида для выбранного языка.
- Переключатель языка вверху редактора, применяет выбранный язык ко всем preview.
- Поиск неиспользуемых ключей и нелокализованных строк.
- Импорт/экспорт .RUS (совместимость со старым редактором) с валидацией символов и разделителей.
- Нелокализуемые идентификаторы (имена флагов, ID событий для отладки, ключи локали) — помечаются особым стилем и не показывают warning.

### Шаблоны (presets)
- Выделить блок событий/строений/армий — сохранить как template.
- Импорт template из библиотеки (встроенные + пользовательские).
- При импорте — переименование ID с разрешением конфликтов.
- Формат template — JSON с метаданными (имя, описание, теги, источник гайда).

### Diff между проектами
- Сравнение двух .map-файлов.
- Список изменений по категориям (карта, события, строения, армии).
- Для каждого изменения — old/new значение и кнопка «перейти к».
- Частичный merge — применение отдельных изменений выборочно.

### Система тегов и заметок (TODO/FIXME)
- На любом объекте карты/событии/строении — заметка (TODO/FIXME/NOTE/HACK).
- Заметки показываются как иконки на карте и в отдельном окне TODO List.
- Сортировка по типу, поиск по тексту.
- Заметки не экспортируются в финальную карту (только в проект редактора).

### Экспорт отчёта в Markdown
- Автоматическая генерация Markdown-файла с описанием карты на основе Map Info.
- Содержание: авторство, версия, настройки, дисклеймеры, список квестов, список сюжетных битв с тактической стоимостью, список поддерживаемых языков, известные проблемы (по состоянию валидаторов).

## 6. Принципы разработки

- **Разделение модели и представления.** Доменные структуры не зависят от UI. UI — тонкий слой над state. Это позволяет менять UI-фреймворк без переработки ядра и писать unit-тесты для логики без запуска UI.
- **Иммутабельные снимки состояния.** State редактора — иммутабелен снаружи, изменяется только через команды. Это даёт undo/redo и атомарность.
- **Поток изменений через команды.** Любое действие — команда. Никаких прямых мутаций state из UI.
- **Реестр объектов как источник истины.** Все dropdown-ы берут данные из реестра (registry). Добавлять новые предметы/юниты = расширять registry, а не редактор.

## 7. Технические ограничения (из гайда старого редактора, обязательно учесть)

Эти ограничения выявлены в гайде Hristos как баги старого редактора. Новый редактор должен исключить их конструктивно или валидаторами:

1. Сохраняющийся кэш между сессиями — чистая инициализация state при открытии/создании проекта.
2. Отрицательные тактические стоимости — валидатор с предупреждением.
3. Вылеты в сложных битвах с высокоуровневыми персонажами — без решения (геймплейный баг), но предупреждать в tooltip.
4. Активация армии на пустой карте — валидатор EmptyMapArmyActivation.
5. Нехватка памяти для маршрута на больших открытых картах со свободным передвижением — валидатор PatrolBounds.
6. Слух/задание без текста, вызывающий относительное событие через 0 часов — валидатор SelfLoopWithoutText.
7. Фонарик + заклинание в одном событии — валидатор EventFunctionComboConflict.
8. Ожидание + подчинённое событие — валидатор EventFunctionComboConflict.
9. Ожидание + текстовое окно в строении (кнопка «Ок» не работает) — без решения, tooltip.
10. Патруль за нижней границей карты — валидатор PatrolBounds.
11. Битва в строении с наложением интерфейсов — валидатор EventFunctionComboConflict (битва в строении).
12. Кастомные союзы — без решения, совет в tooltip: использовать стандартные настройки союзов.
13. События без текста — часть функций не работает — валидатор EventTextRequired.
14. Алгоритм проверки флагов по префиксу (SAD срабатывает для SADDLE) — валидатор FlagPrefixConflict.

## 8. Структура проекта

- `crates/editor-core/` — доменные модели, state, command trait, валидаторы (без UI).
- `crates/editor-serde/` — обёртки над advini и alkahest для save/load.
- `crates/editor-validators/` — реализация валидаторов (отдельный крейт для тестирования).
- `crates/editor-ui/` — egui-слой: окна, панели, виджеты.
- `crates/editor-cli/` — CLI для batch-операций (lint, экспорт в Markdown, дифф).
- `crates/editor-sim/` — симулятор событий.
- `bin/editor/` — точка входа редактора.

## 10. Что НЕ входит в ТЗ

- Геймплейные формулы (инициатива, урон, тактическая стоимость, кривые сложности) — не специфицируются в редакторе, только отображаются.
- Содержание готовых карт (карты, юниты, предметы) — это контент, который авторы делают в редакторе, а не часть самого редактора.
- Баланс конкретных карт — ответственность картодела, редактор только даёт инструменты для анализа.
- Сетевой код для мультиплеера — если потребуется, отдельная подсистема.
