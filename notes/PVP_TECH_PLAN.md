## 1. UI для ПВП

### 1.1 Список комнат (лобби-браузер)

**Экран** `Menu::PvpLobby` (новый вариант `Menu` в `wgpu_ui/src/state.rs`).

Данные комнаты (DTO, передаётся сервером в ответе `ListRooms`):

```
PvpRoomSummary {
  id: RoomId (u64/uuid),
  title: String,
  mode: RoomMode,            // Battle | MapGame
  map: Option<String>,       // для MapGame (например "Проклятое озеро")
  rules_preset: Option<String>, // имя пресета правил (см. 1.4)
  rated: bool,
  players: u8, players_max: u8,   // 2 для Battle, 2..N для MapGame
  spectators: u8, spectators_allowed: bool,
  status: RoomStatus,        // Lobby | InGame | Finished
  host: AccountBrief,
}
```

**Экранные зоны** (UI-мир 1920×1080, стиль существующих окон `screens.rs`):
- Табы-фильтр сверху: «Все / Битвы / Карты» + чекбокс «только открытые».
- Таблица комнат: заголовок | режим | карта | хост | игроки | зрители | статус | кнопка «Войти»/«Наблюдать» (grayed если нет мест/запрещены).
- Кнопка «Создать комнату» → экран 1.3.
- Кнопка «Обновить», авто-refresh каждые N сек (сервер шлёт `RoomList` push при изменениях — лучше push, чтобы не поллить).

**Новые сообщения протокола** (расширение `ClientMessage`/`ServerMessage`):
- `ClientMessage::ListRooms` → `ServerMessage::RoomList(Vec<PvpRoomSummary>)`
- `ClientMessage::JoinRoom { room, as_spectator }` → `ServerMessage::JoinedRoom(RoomView)` / `JoinRejected(reason)`
- `ClientMessage::LeaveRoom`
- `ClientMessage::CreateRoom(RoomConfig)` → `ServerMessage::RoomCreated(RoomId)`
- Изменение статуса комнаты: `ServerMessage::RoomUpdate(PvpRoomSummary)` — пуш всем в лобби.

### 1.2 Разделение битв и карт-игр

`enum RoomMode { Battle, MapGame }` — разъезжаются ветки запуска:
- **Battle**: после старта оба игрока попадают в `Menu::Battle`; состояние — `BattleInfo`, гоняется `handle_action` (`battlefield.rs`), тики хода — по действиям игроков.
- **MapGame**: обычный `Executor` на сервере (как сейчас `GameServer::update`), карта берётся из конфига комнаты; «Проклятое озеро» — просто пресет карты + правила (см. 1.5 battle-royale).

Сервер: один процесс → `HashMap<RoomId, Room>`, `Room { config, players, spectators, state: RoomState }`, где `RoomState::Battle(BattleInfo) | MapGame(Executor)`. Внутри комнаты протокол — существующий `ClientMessage`, обёрнутый в `ClientMessage::RoomMsg(...)`.

### 1.3 Создание комнаты: полная форма настроек

Экран `Menu::PvpRoomSetup`. Конфиг (DTO `RoomConfig`, серде-сериализуемый, сохраняется как пресет):

**Общие**
- `rated: bool` — рейтинг/не рейтинг (эло считается только для rated).
- `mode: RoomMode`.
- `spectators: SpectatorPolicy { Allowed, Forbidden }`.
- `rules_preset_id: Option<String>` — применение пресета из маркетплейса (1.4) предзаполняет всё ниже.

**Настройки одной битвы (mode=Battle)**
- `gold_per_side: u64` — бюджет.
- `allow_items: bool` — разрешена ли покупка артефактов в сетапе.
- `allow_spells: { purchase: bool, use_in_battle: bool }` — покупка и применение заклинаний.
- `game_modification: GameModification` — «выбор модификации игровой»: enum { None, FogOfWarDraft, RandomIniBonus, Custom(String) } (см. идеи 6.1).
- `draft: DraftRules` — совместный бан 3 юнитов с каждой стороны: `bans: [Vec<UnitId>; 2]`, порядок ABBA (идея 6.2).
- `coin_flip_initiative: bool` — «случайная +1 инициатива у одной из армий»: реализация — на `BattleInfo::start` с вероятностью 50% одной армии `modify.speed.add = Some(1)` всем живым юнитам; это ровно `add_modify_effect_ex`-семантика, но проще прямым слоем: `troop.get().unit.modify.speed.add = Some(1)`.
- `max_units: Option<u8>` — лимит юнитов на армию (при валидации армии: `army.troops.len() <= max_units`).
- `max_mages: Option<u8>` — лимит магов (`UnitInfo.magic_type.is_some()`).
- `reinforcements: ReinforcementRules { disabled, buy_only, free_wave }` — покупка подкреплений в процессе (появляются в резерве, Field::Reserve; сеттить через `Army::set_unit_at` + списание золота).
- `banlist_units: Vec<UnitId>`, `banlist_items: Vec<ItemId>` — полный запрет (не только драфт-баны).
- `limit_kind: LimitKind { Gold, Points, None }` + `points_table: Option<HashMap<UnitId, u64>>` — поинтовая система: цена юнита задаётся организатором комнаты (дефолт = `cost_hire`).

**Валидация команды старта**: армия каждого игрока проходит `RoomRules::check_army(&Army, &GameInfo) -> Vec<RuleViolation>` — единая точка, её же использует валидатор в UI сетапа (зелёная/красная подсветка сразу).

### 1.4 Маркетплейс наборов правил (пресеты)

- `RulesPreset { id, name, author, description, tags, config: RoomConfig }`, формат — JSON (serde), хранение:
  - локально: `dt/rules-presets/*.json`;
  - «маркетплейс» v1: общий каталог — статический репозиторий/каталог файлов, редактор комнат умеет «импорт по ссылке/файлу»;
- UI: вкладка «Пресеты» в лобби: список, поиск по имени/тегам, «Применить к новой комнате», «Экспортировать мои настройки как пресет».
- Не требуем сервер-стор в v1: пресет можно просто прислать файлом.

### 1.5 Эло и режимы рейтинга

- **Рейтинговые пулы**: `rating_pool: Battle1v1 | MapBattleRoyale | MapStandard` (расширяемо).
- **Мат. часть**: Glicko-2 (лучше классического Elo: есть RD — честнее при малом числе игр; реализация ~200 строк, крейт `glicko2` есть, но можно и руками). Хранить: `{ account_id, pool, rating, rd, volatility, wins, losses, last_played }`.
- **Начальный рейтинг**: 1500, RD 350. Не-rated игры не трогают рейтинг, но пишутся в историю.
- **Топы**: экран `Menu::PvpLeaderboard`, таблица `SELECT ... ORDER BY rating DESC LIMIT 100` по пулу; вкладка «своя позиция».
- Матчмейкинг v1 — через лобби (ручной вход в комнаты). Автопоиск (queue по эло-диапазону) — фаза 2: `ClientMessage::FindMatch { pool, range }`.

### 1.6 Регистрация/аккаунты

- **Варианты входа**: (а) логин+пароль, (б) Discord OAuth2 (Application → OAuth2 code flow; получить `discord_id`, `username`, аватар).
- **Пароли — только хэш**: аргон2id (крейт `argon2`). Хранить `password_hash`, salt внутри хэша. **Никогда** plaintext; сессии — токен (случайные 32 байта, base64) в `sessions` таблице + на клиенте в конфиге.
- Таблицы (SQLite через `sqlx`/`rusqlite` на сервере; сервер и так async-tokio — sqlx удобнее):
  - `accounts(id, login UNIQUE, discord_id UNIQUE NULL, password_hash NULL, created_at, display_name)`
  - `ratings(account_id, pool, rating, rd, volatility, wins, losses)`
  - `match_history(id, pool, room_id, started_at, winner_account, loser_account, rated, replay_path)`
- Дискорд-аккаунт без пароля: `password_hash NULL` — вход только через OAuth.
- Идентичность в игре: `Player.account: Option<AccountBrief>` (серверная правда; клиент получает только display_name + дискорд-таг — не больше, приватность).

### 1.7 Чат (живёт столько же, сколько комната)

- Транспорт — те же websocket'ы. Сообщения: `ClientMessage::Chat { room, text }` → `ServerMessage::ChatMsg { room, from, text, at }`.
- Каналы: room-чат общий; приватные сообщения — v2 (не сейчас).
- Сервер: broadcast всем участникам комнаты (игроки + зрители), лимит длины (например 300 символов), rate-limit (не чаще 5 сообщений/10 сек), хранение последних 200 строк в памяти комнаты + отправка истории при входе.
- UI: панель чата в комнате/лобби справа, сворачиваемая; в бою — тонкая полоса снизу поверх (не мешает кликам по полю — полупрозрачная, скрывается по F2). Показывать `display_name` с цветом по армии; системные сообщения («X присоединился», «батл начался») — серым.

### 1.8 Подсказка «где чья армия» в бою

Минимум из трёх (сделать 1+2, они дешёвые):
1. **Цветная рамка-подложка** карточек: своя армия — зелёная, враг — красная (`draw_rect_lines` под карточкой в `battle_view.rs`, как выделение в `building_view.rs`).
2. **Плашка заголовка**: в верхней строке «ВЫ — армия слева/зелёные» + мини-иконка флага у каждой карточки.
3. **Ховер-пометка**: при наведении на юнита — «ВАШ/ВРАГ» первой строкой тултипа.
Важно: в PVP обе стороны уже получают `State` и рисуют армию1 слева — путаница из-за того, что игрок не знает, какой из армий управляет. Ответ хранится в `BattleInfo` (или в `RoomView`): `your_army: usize` — сервер присылает при старте; рендер сравнивает с ним. Для наблюдателей обе армии нейтральные, помечаем «наблюдение».

### 1.9 Линейка ходов юнитов

Сделать полноценный виджет:
- Данные уже есть: `BattleInfo.move_order: Vec<BattleUnit>` (порядок на текущий раунд), `active_unit` (индекс текущего).
- UI: горизонтальная полоса сверху боевого экрана (под заголовком): последовательность портретов (`get_unit_texture`), у каждого — бейдж с числом ходов (`unit.moves` — сколько действий осталось в ЭТОМ окне активности; и/или `max_moves` — сколько всего). Текущий активный юнит — подсветка рамкой + стрелка.
- Поведение: полоса листается (если юнитов > 12 — скролл), при новом раунде (`next_move_seq` пересобирает `move_order`) — анимация сдвига не обязательна, достаточно перерисовки.
- Для PVP и одиночной игры — один и тот же виджет (переиспользование рендера битвы как в ТЗ).

## 2. Архитектура сервера (сводка)

- Один бинарник `dt_server` уже есть — расширять его.
- Компоненты:
  - `RoomManager`: `HashMap<RoomId, Room>`; создание/вход/выход/старт; push-обновления в лобби.
  - `Auth`: SQLite (accounts, sessions), argon2, дискорд OAuth2.
  - `Rating`: glicko-2, обновление по завершении rated-игры; запись в `match_history`.
  - `Chat`: per-room broadcast, история, rate-limit.
  - `Game`: текущий `GameServer`/Executor внутри комнаты (рефакторинг: сейчас сервер — на одну игру, сделать структуру «комната владеет игрой»).
- Протокол: версионирование `ProtocolVersion` в handshake (иначе сломаем совместимость клиента/сервера при развитии).
- Реплеи: сохранять последовательность `ClientMessage` по комнате в файл — база для будущих «смотреть реплей/перемотка» (дёшево, полезно).

## 3. Этапы (порядок работ)

1. **Протокол комнат** (RoomConfig/ListRooms/Join/Leave/Start) + серверный RoomManager. Клиент: экран лобби со списком (без эло/аккаунтов, локальный ник).
2. **Битва в комнате**: старт rated-less битвы по правилам (gold, bans, max_units...), `your_army`, подсказка чья армия (1.8), линейка ходов (1.9).
3. **Чат** (1.7).
4. **Аккаунты**: логин/пароль + argon2; затем Discord OAuth. Привязка к комнатам/топам.
5. **Эло** (glicko-2) + история матчей + топы; пометка rated в конфиге комнаты.
6. **MapGame-комнаты** (Executor в комнате) + «Проклятое озеро» как battle-royale пресет (правила: все против всех, зоны — отдельно, см. идеи 6.4).
7. **Маркетплейс пресетов** (1.4) + автопоиск матчей (очередь по эло).

## 5. Дополнительные идеи правил (просили «придумай сам»)

6.1. **Модификации игры**:
- FogOfWarDraft — армии противника скрыты до старта (выбирается «вслепую»);
- RandomIniBonus — одной из армий +1 инициатива (уже в списке), или ±10% золота;
- MirrorMatch — оба играют одинаковыми наборами юнитов;
- BlindGold — бюджет скрыт до старта.

6.2. **Драфт-баны**: порядок ABBA, таймер на бан (30 сек, пропуск = без бана), повторный бан недоступен, если юнит уже забанен. Баны фиксируются в `RoomConfig` и рассылаются.

6.3. **Тайм-контроль**: шахматные часы на ход (например 60 сек/ход, 3 запасных «экстра»). По истечении — автопропуск хода. Нужно для рейтинговых игр (анти-затягивание).

6.4. **Battle Royale на карте**: N>2 игроков, старт по углам карты, зона (кольцо тайлов, вне зоны — потери hp армии каждый тик), победа — последняя выжившая армия. Сервер: тикExecutor + список «alive»; эло — отдельный пул.

6.5. **Ограничения по составу**:
- «без магии вообще», «только рукопашные», «максимум 1 герой», «запрет нежити/зверей» (фильтры по `UnitType`);
- «армия из одного юнита-босса» (поинтовый лимит высокий);
- «симметричные армии» — система копирует состав первого игрока второму.

6.6. **Экономические правила**:
- процент от бюджета возвращается после боя за выживших (как «продажа»);
- «аукцион»: оба игрока скрыто назначают цену за право первого хода.

6.7. **Условия победы в битве**: по умолчанию — уничтожение; дополнительно «на очки за N ходов» (MAX_MOVES уже есть — очки = сумма hp выживших), «убить героя».

6.8. **Наблюдатели с задержкой** (анти-стримснайпинг): трансляция наблюдателю с задержкой 2-3 хода.

6.9. **Комнатные роли**: хост может назначить «со-хоста», кикать, банить по аккаунту; черный список комнат.

6.10. **Статистика профиля**: winrate по юнитам (какие юниты чаще в победных составах), любимые пресеты — агрегаты из `match_history` (дешево, приятно для топов).

## 6. Что НЕ делаем в v1 (осознанно)

- Автоматический серверный fog-of-war (большой кусок; v1 — доверенный клиент).
- Реплеи с перемоткой/просмотром (запись сообщений — да, просмотр — позже).
- Мобильный клиент, p2p без сервера, турнирная система (сетки), сезонные сбросы эло.
- Сквозная интеграция с Discord-ботом (кроме OAuth-логина).
