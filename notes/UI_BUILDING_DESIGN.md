# UI_BUILDING_DESIGN — устройство окон строений (v1, старая версия)

> **Статус: это первая версия описания.** Она составлена по ТЗ пользователя и по
> скриншотам оригинальной игры (`пример-*.png/webp` в корне). Правки ВНОСИТЬСЯ МОГУТ
> и будут — при имплементации структура может уточняться. Не считать финальным контрактом.

## Общие принципы (из ТЗ + скриншотов оригинала)

1. **Окно строения — отдельный экран** (`Menu::Building`), а НЕ оверлей внутри `draw_map`.
   Карта под окном **рендерится** (последним состоянием камеры — запечённая текстура),
   но **не обрабатывает ввод**: WASD/пан/зум/клики по карте отключены, пока открыто строение.
2. Окно **меньше вьюпорта** (~85-90%), рисуется **поверх** карты; карта видна по краям
   (в оригинале — тень/затемнение вокруг рамки).
3. **Каркас** (см. `пример-найм-1.png`, `пример-окно-отряда.webp`):
   - Заголовок строения вверху по центру; кнопка **X** справа вверху (выход).
   - **Левая колонка** — вертикальные «таблички»-вкладки по содержанию строения:
     «Меню» (главное), «Рынок», «Рекруты», «Заклинания»; внизу отдельная зона **«Выход»**.
     Вкладка видна только если строение её поддерживает (market/recruitment/spells_to_learn).
   - **Правая зона** — содержимое активной вкладки.
4. Скрины в UI-мире 1920×1080 (как весь wgpu_ui), поверх — пасс с HUD-камерой.

## Вкладки

### Главное меню (всегда)
- **Фон-картинка** строения (дебаг: `Menu.png` из `assets/Window/`).
- **Ниже — окно слухов и событий** строения (подложка «бумага» + текст, стиль
  `пример-окно-события.webp`: заголовок, текст, иконки предметов).
- Источник слухов: события строения (`MapBuildingdata.events` → events.ini);
  пока данных нет — заглушка-текст.

### Рынок (если `building.market.is_some()`)
- **Два списка** (см. ТЗ): товары рынка (слева) и инвентарь армии игрока (справа).
- **Перекидывание предметов** кликом: клик по товару рынка = «выбрать к покупке»,
  клик по предмету игрока = «выбрать к продаже». Выбранное подсвечивается.
- **Кнопка сделки** («Совершить сделку»): выполняет выбранные операции пачкой
  (покупка за полную цену из `Market::buy`, продажа за **50%** стоимости —
  `Market::sell`), после чего показывает **результат сделки**: что куплено/продано,
  дельта золота.
- Иконки предметов — `ItemInfo.icon`; tooltip при hover: имя+описание+цена.

### Рекруты / Казарма (найм) (если `recruitment.is_some()`)
- **Верх**: линейка юнитов на найм — карточки (портрет из `unit_{icon_index-1}.png`,
  кнопка **«Нанять»**, подпись **«Цена = N»**), как в `пример-найм-1.png`.
- **Справа/поверх**: крупная **карта статистик** юнита — на которого **hover или клик**
  (как карточка в `пример-найм-2.png`: портрет крупно + статы строками).
- **Низ**: моя армия сеткой 6×2 (12 слотов, `max_troops`): пустые слоты —
  картинки-заглушки (front/backyard/tent), занятые — карточка юнита с мини-статами
  (A/D/Mnv/Ini/Hits) как в бою.
- **Drag и клик-мув**: перетаскивание юнита мышью в другое место армии ИЛИ
  клик-выбрать → клик-вставить (оба режима). Перестановка меняет `troop.pos`.
- **Лечение**: у раненых юнитов кнопка **«Лечить»** с ценой (как синяя кнопка
  «Лечить Цена = 79» в оригинале). Опции: **«Лечить до конца»** (полная цена) и
  **«Лечить на N золота»** (сколько хватает).
- **Воскрешение** (только город `Town`/`Village` и церковь `Church`): кнопка
  **«Воскресить»** на мёртвых юнитах армии (трупы остаются в `troops` с hp=0),
  цена = `cost_hire`.
- Найм выполняет `Recruitment::buy` (списывает золото, уменьшает счётчик).

### Заклинания (если `spells_to_learn` непустой)
- Список заклинаний строения (эффекты из реестра `Effects`): имя, описание,
  **цена**, кнопка «Купить».
- Покупка записывает эффект юниту-герою (глава армии), списывает золото.
- Цены заклинаний в данных пока не моделируются — берём номинал из
  `game_settings`/константы; INI-конфиги **не трогаем** (по указанию).

### Выход
- Кнопка **X** в рамке + вкладка/зона **«Выход»** слева внизу + Esc.
- Возврат на карту (карта снова принимает ввод).

## Вход в окно (дабл-клик)

- **Двойной клик ЛКМ по строению на карте** (окно < 400 мс между кликами, тот же тайл):
  - если армия игрока стоит в **хитбоксе** строения (`hitmap[tile].building == id`
    и армия в хитбоксе) → открыть окно (`Menu::Building { building, tab: Main }`);
  - иначе → `ClientMessage::GoTo(tile)` — путь строится, армия идёт
    (существующая механика). Открытие после прибытия — повторным дабл-кликом.
- Дабл-клик по строению **только** для строений; одиночный клик работает как раньше (GoTo).

## Состояние (wgpu_ui)

```rust
pub struct BuildingUi {
    pub building: usize,           // индекс в gamemap.buildings
    pub tab: BuildingTab,          // Main / Market / Recruits / Spells
    pub inspect: Option<usize>,    // hover/выбранный юнит для карты статов
    pub market_pick: Vec<usize>,   // выбранные к покупке (индексы market.items)
    pub player_pick: Vec<usize>,   // выбранные к продаже (позиции army.inventory)
    pub deal_log: Vec<String>,     // результат последней сделки
    pub last_click: Option<(f64, [f32; 2])>, // для дабл-клика
}
pub enum BuildingTab { Main, Market, Recruits, Spells }
```

- Хранится в `UiState` (`state.building: Option<BuildingUi>`), НЕ в `Menu` —
  карта остаётся `Menu::Map`, окно поверх.
- **Блокировка ввода карты**: в `map_screen`, если `state.building.is_some()`,
  `draw_map` рисует, но весь блок ввода (WASD/ПКМ/колесо/клик) пропускает.

## Правки ядра dt_lib (уже внесены, покрыты тестами)

- `Recruitment::buy` — фикс: `Result<usize, ()>` (Ok при найме), checked-золото.
- `Market::sell(seller, inventory_pos) -> Result<u64>` — продажа за **50%**.
- `Market::new/update/buy/can_buy/get_item_cost` — pub (для UI).
- `heal_cost(troop)` — 1 золото за 1 недостающего HP.
- `heal_for_gold(troop, gold)` — лечит на сумму/до конца.
- `resurrect_cost(troop)` = `cost_hire`; `resurrect(troop, gold)` — полное HP,
  caller сам списывает золото с армии (раздельное заимствование troop/army).
- Тесты: `dt_lib/src/battle/tests.rs` (`*_building_*`, `recruitment_buy_*`,
  `market_*`, `heal_*`, `resurrect_*`).
- **INI-конфиги строений не трогаем** (данные в `dt/Objects.ini` и картах неполные —
  UI работает с тем, что уже распарсено в `MapBuildingdata`).

## Что НЕ переносим из старых заметок

- `Menu.png`-skin окно на весь экран — у нас окно строения меньше вьюпорта.
- Полосу времени/ресурсов внизу (мана/доход/выплата) — в оригинале есть, но в ТЗ
  не требуется; достаточно полосы «Деньги» внутри вкладки найма/рынка. При желании
  добавить позже.
