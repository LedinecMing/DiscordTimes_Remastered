# Справочник: имплементация конвертера LIT/UGS → PNG на Rust

**Для агента-имплементатора.** Всё, что нужно для написания конвертера ресурсов игры
«Времена раздора» (Discord Times, Aterdux Entertainment, 2003) в PNG.
Статусы фактов помечены: ✅ доказано (дизассемблер/эмуляция/IL), 🔶 доказано эмпирически.
Формат расшифрован ПОЛНОСТЬЮ: эталонный декодер — `lit_converter/lit2png.py` (эмуляция
нативного кода), чистый Python/Rust повторяет его с точностью ±1 LSB.

---

## 1. Контекст

- Игра: «Времена раздора» = Discord Times (Aterdux Entertainment, Беларусь, 2003).
- Ресурсы: `.lit` (изображения, «BMP со слоями и прозрачностью» по определению автора формата),
  `.ugs` (анимационные файлы движка UGRAPH).
- Официальный тул разработчика: `LITView.exe` (Delphi, PE32, 2009) — «LIT View & Convert».
- Комьюнити-тул: `TgaLitConverter.exe` (.NET, WinForms) — читает/пишет LIT в **сыром** (несжатом)
  варианте формата.
- Файлы игры (2003) декодируются штатным декодером LITView (2009) **без каких-либо отличий**:
  эмуляция `decode_plane` (0x419148) даёт корректные картинки всех 10 файлов. Формат один.
  (Осторожно: при Own-реимплементе легко получить «шум» из-за двух классических ловушек —
  см. §6: ориентация базиса IDCT и порядок умножения матрицы.)

## 2. Контейнер LIT — проверено полностью

```
offset 0   char[4]  magic = "LIT\0"          (4C 49 54 00)
offset 4   u32le    W                     (ширина, пиксели)
offset 8   u32le    H                     (высота, пиксели)
offset 12  u32le    FLAGS                 (битовая маска, см. ниже)
offset 16  ...      данные плоскостей
```

### 2.1 Флаги (поле @12)

| бит | значение | ✅ источник |
|-----|----------|-------------|
| 0x2 | макроблоки 16×16, хрома 4:2:0 (полуразрешение). Если сброшен — блоки 8×8, хрома 4:4:4 | дизасм LITView `0x419aa8` |
| 0x4 | RAW-режим: после заголовка идёт несжатый попиксельный YUV (Y,U,V), W*H*3 байт | дизасм `0x419983` + IL TgaLitConverter |
| 0x8 | в файле есть 4-я плоскость — альфа | дизасм `0x41996b`, `0x419d68` |

Фактические флаги в игровых файлах: `2` (BI_*, GP-*, Army-Death, Authors-Splash) и `0xA`
(DownCorner — с альфа-плоскостью).

### 2.2 Геометрия (режим DCT, флаг 0x4 сброшен)

```
если FLAGS & 2:                       иначе (8×8):
  BW = round_up(W, 16)                  BW = round_up(W, 8)
  BH = round_up(H, 16)                  BH = round_up(H, 8)
  ybx = BW/8,  yby = BH/8               ybx = BW/8, yby = BH/8   (сетка Y-блоков 8×8)
  cbx = BW/16, cby = BH/16              cbx = ybx,  cby = yby    (хрома та же сетка)
Y_SIZE   = BW*BH + 128
C_SIZE   = (FLAGS&2 ? BW*BH/4 : BW*BH) + 128
```

### 2.3 Раскладка потока данных после заголовка

```
[Y-сегмент: Y_SIZE][U-сегмент: C_SIZE][V-сегмент: C_SIZE][A-сегмент: C_SIZE если FLAGS&8]
```

- Шаги сегментов жёстко зарезервированы; данные внутри могут занимать не всё,
  остаток забит нулями (файлы добиты до ёмкости нулями — проверено на 8 файлах:
  сумма сегментов == размер данных **точно** для всех).
- Для 2003-файлов сегменты всегда заполняют ёмкость целиком (64 колонки, см. ниже).
- Alpha-сегмент шагает на **Y_SIZE** (полная геометрия люмы). Проверено: DownCorner (FLAGS=0xA)
  сходится байт-в-байт только при A-сегменте = Y_SIZE (2176); рабочие конвертеры используют
  `0x80 + 64*n_luma`.

### 2.4 Сегмент плоскости (формат 2009, ✅ валидировано эмуляцией кода)

```
+0    u8[64]   Q   — множители деквантования (по слоту коэффициента)
+64   u8[64]   SP  — селектор колонки пула (по слоту коэффициента)
+128  i8 pool  — пул значений: колонки по T = nbx*nby значений каждая,
                 колонка c начинается с pool[c*T], значение блока b = pool[c*T + b]
```

Алгоритм (декодер `LITView.exe @ 0x419148`, ✅ проверен эмуляцией в Unicorn и
чистым Python с точностью ±1 LSB):
```
для каждого блока b = 0..T-1 (row-major: b = row*nbx + col):
  для слота j = 0..63:
    v = (int8) pool[ SP[j]*T + b ]        // знаковый байт
    block[j] = v * Q[j]                   // block — natural row-major 8×8
  IDCT(block)                             // float, излоу-структура (см. §5)
  пиксель = clamp(round(v_out), 0, 255)   // движок: fistp, затем (v+4)>>3 —
                                          // с учётом масштаба IDCT = f уже готов
  записать блок в плоскость: plane[(row*8+y)*BW + col*8 + x]
```
Индексация: слот j = natural row-major (v=j>>3, u=j&7); SP[j] — колонка пула,
из которой берётся значение этого слота; Q[j] — его множитель. Формула эквивалентна
`coef_c = quant[c] * (int8) pool[layout[c]*T + b]` из README прошлой сессии.

### 2.5 RAW-режим (FLAGS & 4) — ✅ полностью (это пишет TgaLitConverter)

```
offset 16: W*H триплетов (Y, U, V) — по байту на канал, построчно сверху вниз
R = Y + 1.402·(V−128)
G = Y − 0.34414·(U−128) − 0.71414·(V−128)
B = Y + 1.772·(U−128)
кламп 0..255
```
Заголовок, который пишет TgaLitConverter: `"LIT\0"` + W:u16le@4 + H:u16le@8,
остальные байты заголовка 0 ⇒ FLAGS=0 у его файлов (⚠️ такие файлы игровой движок
трактует как DCT 8×8 — комьюнити-тул не полностью совместим с игрой).

## 3. UGS — ✅ полностью

Файл = **последовательность кадров** без общего заголовка:

```
кадр: u16le W, u16le H, затем W*H значений u16le
```

- Ask.ugs = ровно 50 кадров 40×40 (по 3204 байта: 4 + 40·40·2; заголовок каждого кадра `28 00 28 00`).
- Интерпретация пикселя: `v2 = v XOR 0xAAAA`; **старший байт — яркость (L), младший — альфа (A)**
  (формат A8L8, побайтово перевёрнутый). Проверено: именно XOR-интерпретация даёт гладкую
  яркость (метрика 4.79 против 43.9 у RGB565) и корректную маску прозрачности.
- 0xAA/0xAAAA — нейтральный «пустой» фон (alpha=170); для PNG-прозрачности используйте
  альфу из младшего байта напрямую.

## 4. Пост-обработка плоскостей (✅ дизассемблер 0x41959c, 0x4196dc)

### 4.1 Деблокинг (применяется ТОЛЬКО к U и V, до апсемплинга)

Для каждой границы между 8×8 блоками (сначала горизонтальные границы блок-рядов,
затем вертикальные границы блок-колонок):

```
граница между соседними пикселями a|b (по разные стороны границы):
  d = (a − b);  если d < 0: d += 3;  d >>= 2      // арифметический сдвиг, округление к нулю
  a −= d;  b += d
```
Порядок обхода: для блок-рядов row=1..nby-1 по всем x; для блок-колонок col=1..nbx-1 по всем y.
(Точная последовательность влияет на результат на ±1 — приемлемо.)

### 4.2 Апсемплинг хромы ×2 (только при FLAGS & 2)

1. Репликация: `dst[2y][2x] = src[y][x]`, заполнение нечётных позиций копиями.
2. Сглаживание по X (in-place, слева направо): `new[x] = (2·cur + prev_old + next + 2) >> 2`,
   где prev_old — значение ДО перезаписи; x = 1..W-2.
3. То же по Y.

### 4.3 YUV → RGB (все режимы)

Коэффициенты из init-кода LITView (long double в бинарнике, ✅ извлечены):
```
R = clamp(Y + 1.402·(V−128))
G = clamp(Y − 0.34414·(U−128) − 0.71414·(V−128))
B = clamp(Y + 1.772·(U−128))
```
Округление движка — fistp (к ближайшему чётному на .5); в Rust обычный `v.round()` даёт
расхождение ≤1 LSB только на точных .5.

### 4.4 Альфа (FLAGS & 8)

Альфа-плоскость декодируется тем же decode_plane в буфер размера Y-плоскости,
затем `alpha_surface[i] = plane[i] >> 3` (5-битная альфа, 0..31).
Для PNG: `a8 = round(alpha5 * 255 / 31)` (либо `alpha5 << 3` — визуально близко).

### 4.5 Поверхности движка

16-битные (PicSize = W*H*2 + 4 — 4 байта служебного заголовка поверхности).
Пиксельный формат выбирается в рантайме (LUT-упаковка R5/G6/B5 — RGB565 при 16 бит).
Для PNG-экспорта это не важно: конвертер считает R,G,B в 8 битах напрямую.

## 5. IDCT — ✅ точные константы из бинарника

Классический float-IDCT Лоффлера–Лихтенберга–Мошовица (структура libjpeg islow,
константы @0x426104..0x42615c, извлечены из DATA-секции):

```
0.298631336, 0.390180644, 0.541196100, 0.765366865,
0.899976223, 1.175875602, 1.501321110, 1.847759065,
1.961570560, 2.053119869, 2.562915447, 3.072711026
```

Эквивалентная прямая формула (проверена — расхождение с движком ≤ ±1 LSB после клампа):
```
pixel(x,y) = 1/4 · Σ_{u,v} C(u)C(v)·F[v][u]·cos((2x+1)vπ/16)·cos((2y+1)uπ/16),
C(0)=1/√2, C(else)=1
```
Масштаб: выход движкового IDCT = 8×этой величины, затем `(v+4)>>3` — итог совпадает
с `round(pixel)`. В Rust считайте прямую формулу (или islow-бабочки в f64) и
`clamp(round(f), 0, 255)`.

## 6. Ловушки верификации (как не получить «шум» на правильном коде)

Формат един для 2003 и 2009, но при собственном декодере легко ошибиться так, что
картинка превратится в полосы/мозаику, хотя контейнер прочитан верно. Обе ловушки
реально сработали при реверсе — документирую, чтобы агент их не повторил.

### 6.1 Ловушка №1: ориентация базиса IDCT

Коэффициент в слоте j = natural row-major: **v = j>>3 — вертикальная частота,
u = j&7 — горизонтальная**. В формуле пикселя частота u спарена с координатой **x**,
v — с **y**:

```
pixel(x,y) = ¼·Σ_{v,u} C(u)C(v)·F[v][u]·cos((2x+1)uπ/16)·cos((2y+1)vπ/16)
```

Если перепутать (написать `cos_v(x)·cos_u(y)`), изображение целиком
**транспонируется**: вертикальные стены замка становятся горизонтальными полосами,
а малоконтрастные файлы выглядят «шумом». Симптом: содержимое угадывается,
но «поперёк». Проверка-зонд: подайте в декодер плоскость, где только слот 1
имеет значение 100, Q≡1 — правильный выход: **горизонтальные** полосы
`[17,15,10,4,0,0,0,0]` в каждой строке.

### 6.2 Ловушка №2: порядок умножения матрицы (numpy)

Если матрицу базиса `BAS[c*64 + pixel]` умножать как `coef.dot(BAS.T)` (numpy),
в части окружений результат численно равен `coef.dot(BAS)` — тихая транспонация!
Правильно: `(BAS.T @ coef)` или явный цикл. В Rust проблемы нет, но золотые
векторы, снятые с такого Python-скрипта, будут испорчены — генерируйте их
только через проверенный путь (эталон: `lit_converter/lit2png.py`).

### 6.3 Тесты-калибровщики (все зелёные при правильном декодере)

1. **Слот-зонд** (см. 6.1) — фиксирует ориентацию базиса.
2. **U-нейтральность**: у BI_Castle в U-плоскости колонка 0 пула = 87..114
   (даёт U≈98..128), остальные ≈0; после декода U-плоскость должна быть
   почти плоской (внутриблочные пятна = ошибка позиции/кванта).
3. **DC-карта**: колонка 0 пула по блокам (row-major) повторяет структуру
   яркости сцены (тёмный фон → тёмные пятна).
4. **Ранжирование колонок по RMS**: RMS колонок пула монотонно убывает
   (52.2, 7.0, 4.5, 2.1, … 0) — колонка = частотный ранг.
5. **Эталонное сравнение**: полное совпадение ±1 LSB с выводом
   `lit_converter/lit2png.py` на всех 10 файлах (главный критерий приёмки).

### 7.4 Разбор заголовка (lit/header.rs)

```rust
pub fn parse(buf: &[u8]) -> Result<(LitHeader, Geometry), LitError> {
    if buf.len() < 16 || &buf[0..4] != b"LIT\0" {
        return Err(LitError::BadMagic);
    }
    let w = u32::from_le_bytes(buf[4..8].try_into().unwrap());
    let h = u32::from_le_bytes(buf[8..12].try_into().unwrap());
    let flags = u32::from_le_bytes(buf[12..16].try_into().unwrap());
    if w == 0 || h == 0 || w > 8192 || h > 8192 {
        return Err(LitError::BadDims(w, h));
    }
    let g = if flags & 0x4 != 0 {
        // raw: геометрия не нужна, данные = w*h*3 (+ альфа-сегмент при флаге 0x8)
        todo!()
    } else if flags & 0x2 != 0 {
        let bw = (w as usize + 15) / 16 * 16;
        let bh = (h as usize + 15) / 16 * 16;
        Geometry {
            bw, bh,
            ybx: bw / 8, yby: bh / 8,
            cbx: bw / 16, cby: bh / 16,
            y_size: bw * bh + 128,
            c_size: bw * bh / 4 + 128,
            alpha_size: bw * bh + 128,   // альфа = геометрия люмы (§2.3)
        }
    } else {
        let bw = (w as usize + 7) / 8 * 8;
        let bh = (h as usize + 7) / 8 * 8;
        Geometry {
            bw, bh,
            ybx: bw / 8, yby: bh / 8,
            cbx: bw / 8, cby: bh / 8,
            y_size: bw * bh + 128,
            c_size: bw * bh + 128,
            alpha_size: bw * bh + 128,
        }
    };
    Ok((LitHeader { width: w, height: h, flags }, g))
}
```

### 7.5 Декодер сегмента плоскости (lit/plane.rs)

```rust
pub fn decode_plane(
    seg: &[u8],
    nbx: usize, nby: usize,
    idct: &IdctTables,
) -> Result<Vec<u8>, LitError> {
    let t = nbx * nby;
    if seg.len() < 128 + 64 * t { return Err(LitError::Truncated); }
    let q: [u8; 64]  = seg[0..64].try_into().unwrap();
    let sp: [u8; 64] = seg[64..128].try_into().unwrap();
    let pool = &seg[128..128 + 64 * t];
    let mut out = vec![0u8; nbx * 8 * nby * 8];

    let mut coef = [0f64; 64];
    for b in 0..t {
        for j in 0..64 {
            // ЗНАКОВЫЙ байт пула!
            let v = pool[sp[j] as usize * t + b] as i8 as f64;
            coef[j] = v * q[j] as f64;
        }
        let px = idct.idct2d(&coef);                 // 64 пикселя
        let (br, bc) = (b / nbx, b % nbx);
        for y in 0..8 {
            for x in 0..8 {
                let v = (px[y * 8 + x] + 0.5).floor(); // округление половины вверх
                out[(br * 8 + y) * nbx * 8 + bc * 8 + x] = v.clamp(0.0, 255.0) as u8;
            }
        }
    }
    Ok(out)
}
```

⚠️ Критичные детали:
- байты пула — **знаковые** (`as i8`), 255 = −1;
- `Q[j]` — множитель (умножение, не деление);
- кламп 0..255 сразу после IDCT (плоскости — байты, пост-обработка идёт над клампленными);
- позиция слота j = natural row-major; базис IDCT — см. ловушку №1 в §6.1.

### 7.6 IDCT (lit/idct.rs)

Предвычислить матрицу 64×64 `BAS[c*64 + pixel]` (коэффициент → пиксель) один раз:

```rust
pub struct IdctTables { bas: Vec<f64> } // [64*64], строка = коэффициент

impl IdctTables {
    pub fn new() -> Self {
        let pi = std::f64::consts::PI;
        let cu = |k: usize| if k == 0 { std::f64::consts::FRAC_1_SQRT_2 } else { 1.0 };
        let cos = |k: usize, i: usize| ((2 * i + 1) as f64 * k as f64 * pi / 16.0).cos();
        let mut bas = vec![0f64; 64 * 64];
        for v in 0..8 { for u in 0..8 {
            for y in 0..8 { for x in 0..8 {
                let c = v * 8 + u;          // слот (natural row-major)
                let p = y * 8 + x;
                // u спарена с x, v спарена с y — НЕ ПЕРЕПУТАТЬ (§6.1)!
                bas[c * 64 + p] = 0.25 * cu(u) * cu(v) * cos(u, x) * cos(v, y);
            }}
        }}
        Self { bas }
    }
    pub fn idct2d(&self, coef: &[f64; 64]) -> [f64; 64] {
        let mut out = [0f64; 64];
        for p in 0..64 {
            let mut s = 0f64;
            for c in 0..64 { s += coef[c] * self.bas[c * 64 + p]; }
            out[p] = s;
        }
        out
    }
}
```
Эквивалентна islow-структуре движка (константы §5) с точностью ±1 LSB после клампа.

pub fn deblock_plane(p: &mut [u8], nbx: usize, nby: usize) {
    let bw = nbx * 8; let bh = nby * 8;
    let blend = |a: i32, b: i32| -> i32 { let d = if a - b < 0 { a - b + 3 } else { a - b } >> 2; d };
    // вертикальные границы блок-рядов
    for row in 1..nby { for x in 0..bw {
        let o  = (row * 8 - 1) * bw + x;
        let o2 = o + bw;
        let d = blend(p[o] as i32, p[o2] as i32);
        p[o]  = (p[o]  as i32 - d).clamp(0, 255) as u8;
        p[o2] = (p[o2] as i32 + d).clamp(0, 255) as u8;
    }}
    // горизонтальные границы блок-колонок
    for col in 1..nbx { for y in 0..bh {
        let o  = y * bw + col * 8 - 1;
        let o2 = o + 1;
        let d = blend(p[o] as i32, p[o2] as i32);

        p[o2] = (p[o2] as i32 + d).clamp(0, 255) as u8;
    }}

pub fn decode_raw(buf: &[u8], w: u32, h: u32, flags: u32) -> Result<DecodedImage, LitError> {
    let n = (w * h) as usize;
    let need = 16 + n * 3;
    if buf.len() < need { return Err(LitError::Truncated); }
    let mut rgb = vec![0u8; n * 3];
    for i in 0..n {
        let (y, u, v) = (buf[16 + i*3], buf[16 + i*3 + 1], buf[16 + i*3 + 2]);
        let [r, g, b] = yuv_to_rgb(y, u, v);
        rgb[i*3..i*3+3].copy_from_slice(&[r, g, b]);
    }
    // альфа в raw-режиме у 2003-файлов не встречалась; при FLAGS&8 см. §2.3
    Ok(DecodedImage { w, h, rgb, alpha: None })
}

### 7.9 UGS (ugs.rs)

```rust
pub fn decode_ugs(buf: &[u8]) -> Result<Vec<DecodedImage>, LitError> {
    let mut out = Vec::new();
    let mut off = 0usize;
    while off + 4 <= buf.len() {
        let w = u16::from_le_bytes(buf[off..off+2].try_into().unwrap()) as usize;
        let h = u16::from_le_bytes(buf[off+2..off+4].try_into().unwrap()) as usize;
        if w == 0 || h == 0 || w > 4096 || h > 4096 { break; }
        let px = 4 + w * h * 2;
        if off + px > buf.len() { break; }          // усечённый хвост
        let mut rgb = vec![0u8; w * h * 3];
        let mut alpha = vec![0u8; w * h];
        for i in 0..w * h {
            let v = u16::from_le_bytes(buf[off + 4 + i*2 .. off + 6 + i*2].try_into().unwrap());
            let v2 = v ^ 0xAAAA;                    // снять XOR-маску движка
            let luma = (v2 >> 8) as u8;             // старший байт — яркость
            let a    = (v2 & 0xFF) as u8;           // младший — альфа
            rgb[i*3..i*3+3].copy_from_slice(&[luma, luma, luma]);
            alpha[i] = a;
        }
        out.push(DecodedImage { w: w as u32, h: h as u32, rgb, alpha: Some(alpha) });
        off += px;
    }
    if out.is_empty() { return Err(LitError::Truncated); }
    Ok(out)
}
```
Ask.ugs → 50 кадров 40×40 (белый пульсирующий «?» — курсор подсказки).
Для превью сохраняйте масштаб ×4 (NEAREST) — иначе не разглядеть.

## 9. Подводные камни

1. **Знаковость пула** — `i8`, не `u8` (255 = −1). Самая частая ошибка.
2. **Квантование — умножение** (`v * q`), не деление.
3. **Порядок сегментов**: Y → U → V → (A). Шаги фиксированы, не по фактическому
   заполнению.
4. **16×16 vs 8×8**: меняется и сетка хромы (¼ площади), и апсемплинг (только 16×16).
5. **Кламп до пост-обработки**: плоскости — байты; деблокинг на неклампленном float
   ломает картинку (проверено).
6. **Округление**: движок использует x87 fistp (banker's) и `(v+4)>>3`; обычный `round()`
   даёт ±1 LSB на точных .5 — допустимо, но фиксируйте в тестах допуск ±1.
7. **Альфа 5-бит**: `>>3` при декоде; в PNG масштабируйте `*255/31`.
8. **Кадры UGS**: читайте до первого усечённого заголовка; в Ask.ugs их ровно 50.
9. **DownCorner alpha-шаг**: сумма сегментов сходится при шаге альфы = Y_SIZE (⚠️
   отличается от 2009-дизассембла; сделайте опцией).
10. Не «обрезайте» плоскость до W×H до пост-обработки — деблокинг ходит по padding-области.
