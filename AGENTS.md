## Железные правила (проверено болью)

1. **`SendMut::get()` — блокирующий мьютекс.** Никогда не держи guard на troop и не вызывай функции, которые захватывают ту же troops-ячейку (`attack`, `search_interactions` и т.п.) — мгновенный дедлок. Снапшоть данные короткими guard'ами, guard'ы отпусти, потом вызывай. Сейчас дедлок конвертируется в панику через 5 с с бэктрейсом (`dt_lib/src/mutrc.rs`) — не молчит, но всё равно баг.
2. **Игровую логику менять только с разрешения пользователя, с пояснениями.** Сначала тест, фиксирующий текущее/желаемое поведение, затем правка.
3. Тесты боевой логики живут в `dt_lib/src/battle/tests.rs`; реестр тестовых юнитов id 20–24, эффектов id 0–4 — см. NOTES_battle_logic.
4. Бинарник клиента запускать из каталога `dt/` (там все ассеты), иначе паника на `assets/icon-64.png`.
5. **Параллельный поиск/суммаризация.** Для быстрых параллельных задач поиска
   и суммирования информации по субъекту вызывать суб-агентов (через `task`-батчи).
6. **Приоритет главного агента — не простаивать.** Пока живы фоновые суб-агенты,
   главный агент немедленно спавнит следующие задачи (максимум параллельности):
   очередь работ не должна простаивать, если есть чем занять агента.
7. **Изоляция суб-агентов — git worktree + АБСОЛЮТНЫЕ пути.** Каждый суб-агент,
   меняющий файлы, работает в своём worktree (`git worktree add ../DT_<имя> <ветка>`)
   и проверяет `pwd`/абсолютный путь перед КАЖДОЙ записью. Проверено дважды:
   агенты «утекали» в основное дерево и ломали чужие файлы (server.rs, Cargo.toml).
   Основное дерево — только тому агенту, чья ветка там-checked-out.
8. **Держи HEAD основного дерева собираемым.** Не оставляй незакоммиченный код,
   ломающий сборку, дольше пары минут: коммит «пункт в процессе, тесты зелёные
   по своей зоне» лучше сломанного HEAD. Правки derive-enum'ов
   (ClientMessage/ServerMessage) — одним аккуратным edit + немедленный `cargo check`.
9. **Крейты — только в корне репо** (как dt_lib/, wgpu_ui/), никаких подпапок
   crates/. Новые крейты добавляются в `members` корневого Cargo.toml.
10. **Реестр Registry<T>:** индексация `registry[id]` паникует на чужом/битом id
    (данные карт грязные!) — для данных из карт/сохранений использовать
    `registry.get(id)` и обрабатывать None (паника item.rs:138 — проверено).
11. **Мерджи в интеграционную ветку делает главный агент.** Суб-агенты коммитят
    в свои ветки; `working` — интеграционная, обновляется мерджами из веток
    фич после зелёного прогона тестов. Конфликт Cargo.toml (members) —
    решается объединением списков.
